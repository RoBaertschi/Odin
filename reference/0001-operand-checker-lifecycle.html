Lesson 0001

Operand Checker Lifecycle

A quick reference for how Odin's checker creates, mutates, stores, and consumes operands.

The Shape

An Operand is a temporary semantic result used while checking an expression. It carries mode, type, optional value, source expr, and special payloads for builtins or procedure groups. Source: src/checker.hpp:76.

FieldMeaningTypical consumer question
modeHow this expression may be used.Is this a value, variable, constant, type, builtin, or invalid?
typeThe semantic type after checking.Can it be assigned, converted, called, indexed, or used as a condition?
valueCompile-time value when available.Can this constant fold, choose a when branch, or satisfy a bound?
exprThe AST expression responsible for the operand.Where should diagnostics and untyped updates attach?
builtin_idWhich builtin procedure was named.Which builtin checker path should handle a call?
proc_groupWhich overload set was named.Can context choose one concrete procedure?

The Loop

1. Produce: recursive expression code fills an Operand *. Identifiers are a compact example: constants become Addressing_Constant, variables become Addressing_Variable, type names become Addressing_Type, and unresolved overload sets become Addressing_ProcGroup. Source: src/check_expr.cpp:1841.

2. Normalize: wrapper functions reject modes that are illegal in the current expression context. check_expr rejects no-value and type operands, then rejects tuples where a single value is expected. Source: src/check_expr.cpp:12614.

3. Store: check_expr_base records the result on the AST with add_type_and_value. Untyped expressions also get side-table information for later updates. Sources: src/check_expr.cpp:12580, src/checker.cpp:1893, src/checker.cpp:1925.

4. Consume: statements and declarations ask specific questions of the operand. when requires a constant boolean; if requires a boolean value; assignments compare left and right operands. Sources: src/check_stmt.cpp:676, src/check_stmt.cpp:2581, src/check_stmt.cpp:2518.

Transfer To A C Checker

Use an operand-like struct as the return channel for expression checking. Keep it small and explicit: value category, type, constant value, and source node. Then write context checkers that ask narrow questions: "is this assignable?", "is this scalar?", "is this integer constant expression?", "is this an lvalue?".

Rule Of Thumb

Do not think of operands as runtime machine operands. In this checker, they are semantic control packets that let each enclosing syntax form decide what kind of expression it needed.
