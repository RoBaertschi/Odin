How The Checker Uses Operands

You already know what an operand represents. This lesson is about the operational pattern: the checker fills an operand, normalizes it for the current context, stores its stable facts, then lets enclosing code ask narrow semantic questions.

The One-Sentence Model

An operand is the checker's scratch result for "I checked this expression; here is how it can be used now."

That "how" is the AddressingMode. Odin defines modes for invalid expressions, no-value expressions, values, variables, constants, types, builtins, procedure groups, map indexes, optional-ok forms, SOA variables, and swizzles. Source: src/parser.hpp:9.

The Lifecycle

Produce

Expression-specific code writes into an Operand *. check_ident is the clearest case: lookup an entity, then classify it as constant, variable, procedure value, builtin, type, or procedure group. Source: src/check_expr.cpp:1841.

Normalize

Wrapper entrypoints decide whether that result is legal here. check_expr rejects NoValue, rejects Type, then rejects tuples where a single value is expected. Source: src/check_expr.cpp:12614.

Store

check_expr_base records the operand facts on the AST with add_type_and_value. This is why later code can inspect expr->tav. Sources: src/check_expr.cpp:12580, src/checker.cpp:1925.

Consume

Statement and declaration checkers ask context-specific questions. when asks for a constant boolean; if asks for a boolean; assignment asks whether right operands fit left operands. Sources: src/check_stmt.cpp:676, src/check_stmt.cpp:2581, src/check_stmt.cpp:2518.

Trace One Identifier

Imagine the checker sees x in an expression. It calls the identifier path and starts with an invalid operand. If scope lookup fails, it reports an undeclared-name error and leaves the operand invalid.

If lookup succeeds, the entity kind drives the operand mode. A constant copies its exact value and becomes Addressing_Constant. A variable becomes Addressing_Variable. A type name becomes Addressing_Type. A builtin becomes Addressing_Builtin. An unresolved overload set becomes Addressing_ProcGroup.

The enclosing context then decides what to do. A normal expression context rejects a type. A call context may accept a builtin or procedure group. An assignment context cares whether the left side is assignable and whether the right side can be assigned to its type.

Why This Matters

The checker avoids baking every context rule into expression checking. The expression checker says, "this is what you have." The enclosing syntax says, "this is what I require."

For a C compiler, this maps cleanly to separate predicates: is_lvalue, is_modifiable_lvalue, is_integer_constant_expr, is_scalar, can_assign, and usual_arithmetic_conversions. The operand is the object those predicates inspect and sometimes update.
